# `math`: the bit-for-bit foundations

The simulation must give the same bits as the game on every host. This folder holds the parts
that make sure of it. Every other system uses them.

- The game's `f32` math (`fmath/`): square root, sine, cosine, the inverse trigonometry, `powf`,
  `fmodf` and the game's 3-vectors. Each routine is ported from the game's machine code.
- The random generators (`rng.rs`): eleven `WELL512a` streams. All of them take the frame seed at
  the start of every tick. A port draws from the same stream as the game, in the same order.
- The x86 conversions (`conversions.rs`): a float to an integer as `CVTTSS2SI` does it. Out of
  range or NaN, it gives the "integer indefinite" value, where Rust's `as` saturates.
- The MSVC algorithms (`msvc.rs`): the standard library's sort and hash-map order, as the game was
  compiled with them. The order of equal elements after a sort depends on the algorithm, so the
  port runs the same steps.
- The image's constants (`image.rs`): every constant that a ported routine reads from the game's
  executable, named by its role. A script generates the file.

## In the game

- The C runtime's math routines (musl, from FreeBSD's msun) and `math3d.cpp` (`BVector`).
- The random generators and their seeding (`SeedAll`).

## Files

<!-- files -->
| File | What it holds |
| --- | --- |
| [`angle.rs`](angle.rs) | An angle in radians (`Angle`), with the game's `f32` operations. |
| [`conversions.rs`](conversions.rs) | The x86 conversions the game's code runs where Rust's `as` gives other results: `CVTTSS2SI` into a 32-bit and into a 64-bit register. |
| [`image.rs`](image.rs) | Generated by `aoe2de-exe-re/gen_image_constants.py` from build 158041's constant table (`aoe2de-exe-re/symbols/158041.json`) and image; do not edit. |
| [`mod.rs`](mod.rs) | The bit-for-bit foundations: the game's f32 math, its random generators, the MSVC algorithms whose order shows in the simulation, and the image's constants. |
| [`msvc.rs`](msvc.rs) | The MSVC standard library's algorithms as build 158041 compiled them, where their order shows in the simulation: `std::sort` is an introsort whose order of equal elements depends on the algorithm, so a port must run the same steps. |
| [`rng.rs`](rng.rs) | The engine's random number generators: a `WELL512a` variant in eleven streams, all reseeded at the top of every tick from one frame seed. |
| [`fmath/`](fmath/) | The game's f32 math, bit for bit (checked by `tests/crt_math.rs` against build 158041's own routines on recorded inputs). |
